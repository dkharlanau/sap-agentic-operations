The question behind SAO

Tool calling is not enterprise readiness.

A technically successful call can still be the wrong business action. SAO focuses on evidence, authority, current state, approvals, postconditions, provenance and recovery rather than a demo that merely reaches an API.

SAO-Bench

Failure cases shaped like real enterprise operations.

The corpus separates business impact from the mechanism of agent failure, and makes forbidden actions and execution gates explicit.

CORE · 15

Authority & evidence

Causality, evidence quality, approvals, abstention and business authority.

INTEGRATION · 7

Message operations

Replay, ordering, mapping drift, retry ambiguity and business acknowledgement.

MDG · 7

Master data

Canonical identity, source-of-truth ownership, mapping and governance versions.

PROCESS · 7

Business process

O2C/P2P blocks, deterministic checks and business decision authority.

SECURITY · 7

Agent security

Tool-output injection, poisoned memory, scope escalation and inter-agent trust.

Writes & recovery

Stale approvals, races, idempotency, postconditions and governed compensation.

Run locally

Inspect the assurance harness in minutes.

No SAP tenant is required. The project uses synthetic enterprise scenarios and a runtime-neutral adapter contract.

git clone https://github.com/dkharlanau/sap-agentic-operations.git
cd sap-agentic-operations
python sao.py doctor
python sao.py audit
python sao.py self-test
python sao.py tests
